# OCPP 충전기 통신 보안 가이드

대상: AI-V2G 플랫폼의 OCPP Central System(`src/ocpp/central_system.py`, WebSocket `/ocpp/<충전기ID>`)
상태 기준: 2026-10-02 코드

## 1. 위협과 현재 대응

| 위협 | 영향 | 대응 | 상태 |
|---|---|---|---|
| 무인증 접속(가짜 충전기) | 가짜 계량값 주입, 방전 명령(`aiCommand`) 탈취 | Basic 인증(Security Profile 1), 접속 수락 전 거절 | 구현(`OCPP_AUTH_REQUIRED=1`) |
| 평문 구간 도청·변조 | 비밀번호·계량값 노출 | TLS 종단(wss://) | **운영 필수, 인프라 작업**(§3) |
| 비밀번호 유출 | 충전기 사칭 | bcrypt 해시 저장, 16자 이상 강제, 충전기별 개별 비밀번호·즉시 폐기 | 구현 |
| 접속 폭주(DoS) | 서버 메모리·CPU 고갈 | 동시 접속 한도(`OCPP_MAX_CONNECTIONS`, 기본 400), 신규만 거절하고 기존 충전기 재접속은 허용 | 구현 |
| 거대·깨진 프레임 | 파서 오류, 연결 중단 | 64KB 초과 시 연결 종료(1009), 깨진 JSON·형식 오류는 무시하고 연결 유지 | 구현 |
| 충전기 사칭(다른 ID로 접속) | 타 충전기 상태 덮어쓰기 | 사용자명이 URL의 충전기 ID와 같아야 함 | 구현 |
| 방전 명령의 안전성 | 과방전·계통 영향 | 최적화기 제약(SOC 하한, 방전 횟수 상한)과 별개로 충전기 측 한계 설정 필요 | 충전기·사업자 협의 |

## 2. 운영 설정

```
OCPP_AUTH_REQUIRED=1            # 인증 강제(개발·에뮬레이터는 끄고 둔다)
OCPP_MAX_CONNECTIONS=400        # 동시 접속 한도(목표 150기 + 여유)
```

충전기 자격 등록·폐기(서버에서):

```python
from src.ocpp import security
security.set_credential("CP-001", "<16자 이상 무작위 비밀번호>")   # 해시만 data/ocpp_credentials.json에 저장
security.revoke_credential("CP-001")                                 # 분실·교체 시 즉시 폐기
```

- 충전기마다 **서로 다른** 무작위 비밀번호를 쓴다. 평문은 충전기 설정과 사업자 전달 경로에만 존재해야 한다.
- 인증 실패는 서버 로그에 남는다(`OCPP 인증 실패로 접속 거절`). 같은 충전기의 반복 실패는 비밀번호 추측 시도로 보고 알림 대상으로 삼는다.
- `data/ocpp_credentials.json`은 저장소에 커밋하지 않는다(`data/`는 이미 제외 대상).

## 3. TLS(Profile 2) — 인프라 작업 항목

현재 앱은 평문 `ws://`로 듣는다. 운영에서는 앞단 리버스 프록시(nginx, 클라우드 LB)에서 TLS를 종단하고 `wss://`만 공개한다.

1. 도메인과 서버 인증서 발급(공인 CA). 충전기가 신뢰하는 루트에 포함되는지 확인.
2. 프록시에서 `wss://ocpp.<도메인>/ocpp/<충전기ID>` → 내부 `ws://127.0.0.1:8000`으로 전달, WebSocket 업그레이드 헤더와 `Authorization` 헤더를 그대로 전달.
3. 내부 포트(8000)는 외부에서 접근할 수 없게 방화벽으로 막는다.
4. 프록시에 연결 수·초당 연결 시도 제한을 둔다(앱 한도는 최후 방어선).

충전기가 TLS 1.2 이상을 지원하는지, 사업자 충전기 펌웨어가 Basic 인증 헤더를 보낼 수 있는지 **사업자별 사양 확인이 필요**하다.

## 4. Profile 3(클라이언트 인증서)와 OCPP 2.0.1

- 클라이언트 인증서는 충전사업자의 인증서 발급·갱신 체계가 있어야 하므로, 사업자 확정 후 협의한다. 적용 시 프록시가 인증서를 검증하고 충전기 ID를 앱에 전달하는 구조가 현실적이다.
- V2G(방전)는 OCPP 2.0.1의 `Energy.Active.Export.Register`로만 표현된다. 1.6 충전기는 방전을 표현할 수 없으므로 V2G 대상은 2.0.1(필요 시 ISO 15118)로 한정한다.
- 현재 AI 명령 전달은 `Authorize` 응답에 실어 보내는 근사 방식이다. 상용 CSMS로 갈 때는 서버발 `SetChargingProfile`로 교체하고, 그 호출도 인증된 연결에서만 보낸다.

## 5. 점검 체크리스트(운영 전)

- [ ] 외부에 `ws://`가 열려 있지 않음(`wss://`만 공개)
- [ ] 8000 포트 외부 차단
- [ ] 접속 한도·프록시 속도 제한 설정
- [ ] 자격 폐기 절차 시험(폐기 후 접속 거절 확인)
- [ ] 거절 로그 모니터링 연결
