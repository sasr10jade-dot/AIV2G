# 서비스 관점 전체 점검과 추가 기획 후보 (2026-10-23)

범위: 저장소 전체(서버·화면·설정·문서)를 서비스 이용 흐름(이용자·운영자·외부 공개) 기준으로 점검했다.
수치는 합성 데이터·가정값 기반이며, 아래 "확인함"은 코드 실행·테스트·화면 조작으로 확인한 것만 적는다.

## 3. 남은 위험과 한계 (알고 있는 것)

1. **로그인 잠금은 메모리 기반**: 서버를 재시작하면 초기화되고, 여러 프로세스로 띄우면 공유되지 않는다. 운영 배치 시 공용 저장소가 필요하다.
2. **비밀번호 분실 시 복구 수단이 없다**: 관리자가 계정을 다시 발급하는 방법뿐이다(아래 기획 1순위).
3. **외부 공개 데모는 빠른 로그인이 모두 켜져 있다**: 임시 저장소·가상 데이터만 있지만 주소를 아는 누구나 관리자까지 들어갈 수 있다. 시연 시간에만 열어야 한다.
4. **`/docs`(API 문서)가 외부에서도 열린다**: 호출은 권한으로 막혀 있다.
5. **상품권 지급**: 사업계획서의 "실금 정산 아님" 문구와 충돌할 수 있어 협의·세금 확인이 필요하다. `config/rewards.json`의 `redeem_enabled`로 끌 수 있다.
6. **시·군·구 목록은 제작 시점 행정구역 기준**: 개편되면 `config/regions.json`만 고친다.
7. **데이터가 합성**: 예측·최적화 효과, 포인트 보상 수치는 모두 가정값이다. 실제 충전 기록 61건(영암)만 실측이다.
8. **예측이 최적화 입력이 아님**: 수요 예측은 정확하지만 비용 절감 계산에 쓰이지 않는다.
9. **감사·운영 로그 화면 없음**: 감사로그는 API(`/privacy/audit`)로만 본다.
