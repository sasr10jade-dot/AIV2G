2. 개발 환경 셋업 및 서버 구동 (Windows)
--------------------------------------------------------------------------------
[1단계] 가상환경 생성 및 의존성 설치 (Python 3.14)
  python -m venv venv
  .\venv\Scripts\activate
  pip install -r requirements.txt          # 테스트까지: pip install -r requirements-dev.txt

[2단계] 환경변수 파일 생성
  copy .env.example .env
  * 개발용 간편 로그인 계정(SUPERADMIN_*, DEMO_*)을 .env에 넣으면 /dev 화면의 버튼이 켜진다.

[3단계] 서버 기동 — 두 가지 방법
  (A) 내 PC에서만:   python -m uvicorn src.api:app --host 127.0.0.1 --port 5050 --reload
  (B) 사내 와이파이 개발 서버 — 서버 PC 192.168.35.92(macOS, 계정 jade), 폴더 ~/AIV2G-dev, 포트 5050
        상시 구동: launchd 서비스 kr.aiv2g.dev (로그인 시 자동 시작, 죽으면 자동 재시작)
        코드 반영: cd ~/AIV2G-dev && git pull origin main && launchctl kickstart -k gui/$(id -u)/kr.aiv2g.dev
        로그:      ~/AIV2G-dev/output/dev_server.log
        재학습 배치: launchd kr.aiv2g.retrain(매주 월 05:00) — 등록 scripts/register_retrain_launchd.sh,
                   즉시 실행 launchctl kickstart gui/$(id -u)/kr.aiv2g.retrain, 결과 data/batch/retrain_history.jsonl
        직접 실행: scripts/run_dev_lan.sh 5050      (Windows PC에서는 scripts\run_dev_lan.cmd)
  * 앱 객체는 src.api:app 이다(예전 문서의 src.api.main:app 은 존재하지 않는다).
  * [주의] 서버 PC의 다른 서비스 포트는 쓰지 않는다: 80→3000(Node 앱), 5000(macOS AirPlay), 8000·8443(Proposal AI Studio),
    8080(Docker), 8090(정적 파일). 6000번은 브라우저가 막는 포트라 쓰지 않는다. 다른 서비스의 폴더·프로세스는 건드리지 않는다.
  * 내부망 전용이다. 5050 포트를 공유기 포트포워딩·터널로 외부에 열지 않는다. 서비스가 안정되면 다른 서버로 이관한다.
  * macOS에는 LightGBM이 쓰는 libomp가 없어 run_dev_lan.sh가 scikit-learn에 포함된 libomp를 잡아 준다(Homebrew 불필요).

[4단계] 브라우저 접속 (내 PC면 127.0.0.1, 사내망이면 192.168.35.92)
  - 개발자 진입점 (추천): http://192.168.35.92:5050/dev
  - PC 운영 대시보드 : http://192.168.35.92:5050/dashboard
  - 가입 승인 관리   : http://192.168.35.92:5050/approvals

  - 대화형 API 문서  : http://192.168.35.92:5050/docs

3-2. 2026-11-19 2차 보강 — 서포터즈 리워드 정산 프로세스·미션·VoC·운영
--------------------------------------------------------------------------------
[리워드 모의 정산 프로세스] (계획서 p.30~31, p.48 — src/settlement/ledger.py)
  ① 실적 계측(추론): 차량·일 피크(17~21시) 방전 kWh·과잉발전 흡수 kWh·요금 절감액.
     등록 차량은 방전 참여 동의(v2g_discharge)가 있을 때만 방전 실적을 인정한다.
  ② 재원별 배분: 요금 차익(절감액 비율)·피크 저감(방전 비율)·출력제어 완화(흡수 비율)
  ③ 포인트 = 배분액 × 참여자 배분율 70% ÷ 1원/P (config/vpp_settlement.json points)
  ④ 정산 회차: 산정(POST /vpp/settlement/runs) → 검토 → 확정(/runs/{id}/confirm, 원장 적립)
     또는 취소(/runs/{id}/cancel, 사유 필수). 차량·일 중복 정산 없음, 새 실적 0건이면 회차를 만들지 않는다.
  ⑤ 조회·문의·조정: 차주 GET /owner/points, POST /owner/points/inquiries
     관리자 GET /vpp/settlement/inquiries, POST /vpp/settlement/inquiries/{id}/resolve(포인트 조정 포함), POST /vpp/settlement/adjust
  ⑥ 경제성 검증: GET /vpp/settlement/summary·preview — 지급률, 차량당 월 포인트, 참여 유인 기준, 인센티브 4종 비교
  화면: 웹앱 관리(/admin#reward) '리워드·정산' 탭, 모바일 '리워드' 탭. 대시보드 05 '정산 산정'은 산정만 한다.
  * 실제 금전 지급은 하지 않는다(제도 마련 전, 계획서 p.48). 모든 포인트는 모의.
  * [개발 서버 데이터 주의] 2차 보강 전 방식(즉시 확정)으로 쌓인 정산 기록이 서버 DB에 남아 있으면 새 회차가 그 날짜를 건너뛴다.

[미션·등급] src/settlement/missions.py — /owner/missions, /owner/missions/{id}/claim, /vpp/missions
  방전 참여 켜기·위치정보 동의(일회), 추천 충전 따르기 2회(주간), 피크 방전 10kWh·흡수 20kWh·설문 응답·주행거리 입력(월간)
  기간당 1회 보상, 등급 새싹/브론즈 1,000/실버 5,000/골드 20,000/플래티넘 50,000P. 관리자가 사용 여부·포인트 설정.

[VoC 설문] src/appadmin/survey.py — 웹앱 관리 'VoC 설문' 탭, 모바일 홈 설문 카드, /admin/surveys*, /owner/surveys*
  기본 문항 = 방전 수용도·보상 기대 수준(계획서 p.34). 응답은 차량당 1회, 집계·CSV에 차량 ID 없음.

[데이터·AI 운영]
  - A15 행 단위 출처: curated 저장 시 data_source·generation 컬럼(src/pipeline/source.py annotate_rows)
  - Y2E01 대조 지역 비교: config/comparison_regions.json, GET /ingest/regions/compare, POST /ingest/regions/{id}/sync-temperature
  - Y2B01·02 재학습: src/automation/scheduler.py run_cycle_on_data, scripts/run_retrain_cycle.py(서버 주간 배치 등록)

[화면] 모든 화면 로딩 딤+프로그레스 링(/loading.js, 자동 새로고침은 제외), 대시보드 상단 진행 막대 제거,
       모바일 상단 AX 배지 로고(-V2G), /dev 진입 화면 개편.
[DB] 마이그레이션 v11(정산 회차·문의·거래 재원 내역), v12(미션 설정·완료 이력) — 서버 기동 시 자동 적용.
