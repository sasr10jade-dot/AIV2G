1. 주요 디렉터리 구성
--------------------------------------------------------------------------------
- docs/          : [필독] 인수인계서·PRD·데이터 명세·API 레퍼런스(api_reference.md, 자동 생성)

- tests/         : pytest 테스트 스위트(약 550개)
- android/       : 서포터즈 모바일 TWA 안드로이드 앱 빌드 프로젝트

2. 개발 환경 셋업 및 서버 구동 (Windows)
--------------------------------------------------------------------------------
[1단계] 가상환경 생성 및 의존성 설치 (Python 3.14)
  python -m venv venv
  .\venv\Scripts\activate
  pip install -r requirements.txt          # 테스트까지: pip install -r requirements-dev.txt

[2단계] 환경변수 파일 생성
  copy .env.example .env
  * 개발용 간편 로그인 계정(SUPERADMIN_*, DEMO_*)을 .env에 넣으면 /dev 화면의 버튼이 켜진다.

[3단계] 서버 기동 — 두 가지 방법
  (A) 내 PC에서만:   python -m uvicorn src.api:app --host 127.0.0.1 --port 5050 --reload
  (B) 사내 와이파이 개발 서버 — 서버 PC 192.168.35.92(macOS, 계정 jade), 폴더 ~/AIV2G-dev, 포트 5050
        상시 구동: launchd 서비스 kr.aiv2g.dev (로그인 시 자동 시작, 죽으면 자동 재시작)
        코드 반영: cd ~/AIV2G-dev && git pull origin main && launchctl kickstart -k gui/$(id -u)/kr.aiv2g.dev
        로그:      ~/AIV2G-dev/output/dev_server.log
        직접 실행: scripts/run_dev_lan.sh 5050      (Windows PC에서는 scripts\run_dev_lan.cmd)
  * 앱 객체는 src.api:app 이다(예전 문서의 src.api.main:app 은 존재하지 않는다).
  * [주의] 서버 PC의 다른 서비스 포트는 쓰지 않는다: 80→3000(Node 앱), 5000(macOS AirPlay), 8000·8443(Proposal AI Studio),
    8080(Docker), 8090(정적 파일). 6000번은 브라우저가 막는 포트라 쓰지 않는다. 다른 서비스의 폴더·프로세스는 건드리지 않는다.
  * 내부망 전용이다. 5050 포트를 공유기 포트포워딩·터널로 외부에 열지 않는다. 서비스가 안정되면 다른 서버로 이관한다.
  * macOS에는 LightGBM이 쓰는 libomp가 없어 run_dev_lan.sh가 scikit-learn에 포함된 libomp를 잡아 준다(Homebrew 불필요).

[4단계] 브라우저 접속 (내 PC면 127.0.0.1, 사내망이면 192.168.35.92)
  - 개발자 진입점 (추천): http://192.168.35.92:5050/dev
  - PC 운영 대시보드 : http://192.168.35.92:5050/dashboard
  - 가입 승인 관리   : http://192.168.35.92:5050/approvals
  - 웹앱 관리 (어드민) : http://192.168.35.92:5050/admin
  - 모바일 서포터즈 앱: http://192.168.35.92:5050/app
  - 대화형 API 문서  : http://192.168.35.92:5050/docs

3. 2026-11-19 요구사항 보강 내역 (요구사항정의서 v1.0 미흡·누락 대응)
--------------------------------------------------------------------------------
- K03·B04 AI 성능: 모델 카드 수치를 고정값에서 실제 계산으로 교체
    계획서 기준 Train/Test 80:20 + 시간순 교차검증으로 MAPE·R² 산출
    (src/model/demand_forecast.py evaluate_plan_targets, GET /models/card, GET /models/evaluation)
- C01 출력제어 해소 에뮬레이터: src/optimizer/curtailment.py, GET /vpp/curtailment
    공공데이터 정제 → 과잉발전·피크 시간대 패턴 → 가상 과잉발전 재현 → 적용 전후 출력제어량 비교
- S01 재원별 편익: 고정 비율(62/25/13%) 대신 산식으로 계산(src/optimizer/vpp_revenue.py, GET /vpp/revenue-sources)
- E03 가상 전력 거래·모의 포인트 정산: src/settlement/ledger.py
    관리자: POST /vpp/settlement/run(중복 정산 없음), GET /vpp/settlement/summary, GET /vpp/settlement/preview
    차주: GET /owner/points(모바일 홈 카드)
- D03 V2G 이동형 ESS 집중 실증 그룹(5~10대): src/optimizer/ess_group.py
    GET·PUT /vpp/ess-group, GET /vpp/ess-group/dataset.csv(전용 데이터셋)
- K01 데이터 건수 단위: 계획서 p.16 산출식대로 '차량 운행·충전 세션 + 충전기 세션'으로 집계(src/kpi.py)
- A02 제주 V2G 실증 차종(EV9·아이오닉 9): 가입·승인 차단(config/vehicle_models.json excluded)
- A07 차량 소속(관용/민간): POST /registrations/{id}/affiliation
- K02 예비 Pool(6~9대) 부족 경고와 대체 이력: GET /registrations/reserve-status, POST /registrations/replace
- Q04 위치정보 별도 동의: GET·PUT /owner/consent/location(모바일 마이페이지)
- A04 CPO 수신 실적: config 파일 대신 data/cpo_status.json에 기록, 토큰(token_env) 설정 시 인증 필수
- C04·Y2A02 조건별 분석: 차량 운행조건 축과 운영조건 커버리지(조건별 세션 수) 추가
- E01 결과 엑셀 '한계·개선 기준' 시트 추가 / D05 추천 설명 표기 정정(규칙형 설명)
- DB 마이그레이션 v10 자동 적용(virtual_trades, point_ledger, ess_group_members, vehicle_replacements,
  vehicle_registrations.affiliation) — 서버 첫 기동 시 curated.db에 추가 전용으로 반영된다.
- 가정값은 config/vpp_settlement.json(verified=false)에 있다. 확정되면 값을 바꾸고 verified=true로 전환.
