2. 개발 환경 셋업 및 서버 구동 (Windows)
--------------------------------------------------------------------------------
[1단계] 가상환경 생성 및 의존성 설치 (Python 3.14)
  python -m venv venv
  .\venv\Scripts\activate
  pip install -r requirements.txt          # 테스트까지: pip install -r requirements-dev.txt

[2단계] 환경변수 파일 생성
  copy .env.example .env
  * 개발용 간편 로그인 계정(SUPERADMIN_*, DEMO_*)을 .env에 넣으면 /dev 화면의 버튼이 켜진다.

[3단계] 서버 기동 — 두 가지 방법
  (A) 내 PC에서만:   python -m uvicorn src.api:app --host 127.0.0.1 --port 5050 --reload
  (B) 사내 와이파이 개발 서버 — 서버 PC 192.168.35.92(macOS, 계정 jade), 폴더 ~/AIV2G-dev, 포트 5050
        상시 구동: launchd 서비스 kr.aiv2g.dev (로그인 시 자동 시작, 죽으면 자동 재시작)
        코드 반영: cd ~/AIV2G-dev && git pull origin main && launchctl kickstart -k gui/$(id -u)/kr.aiv2g.dev
        로그:      ~/AIV2G-dev/output/dev_server.log
        재학습 배치: launchd kr.aiv2g.retrain(매주 월 05:00) — 등록 scripts/register_retrain_launchd.sh,
                   즉시 실행 launchctl kickstart gui/$(id -u)/kr.aiv2g.retrain, 결과 data/batch/retrain_history.jsonl
        일 배치:   launchd kr.aiv2g.daily(매일 04:30) — 데이터 결합 → 예측 갱신 → 아크릴 오차 → 차량별 충전 계획·앱 추천
                   등록 scripts/register_daily_launchd.sh, 즉시 실행 launchctl kickstart gui/$(id -u)/kr.aiv2g.daily,
                   결과 data/batch/daily/<날짜>/, data/batch/daily_history.jsonl, 로그 output/daily.log,
                   관리자 조회 GET /kpi/daily-batch. 추천은 앱 추천 기록에만 남기고 문자·푸시는 보내지 않는다.
        직접 실행: scripts/run_dev_lan.sh 5050      (Windows PC에서는 scripts\run_dev_lan.cmd)
        HTTPS(휴대폰 앱 설치·PWA용): 포트 5443, launchd 서비스 kr.aiv2g.dev-https, 로그 output/dev_server_https.log
                   휴대폰 브라우저는 http 주소에서 앱 설치·서비스 워커를 막으므로, 내부 루트 인증서로 HTTPS를 연다.
                   인증서: scripts/make_lan_cert.sh 192.168.35.92 → ~/AIV2G-dev/certs/ (저장소 제외, 개인키 권한 600,
                   서버 인증서 825일 — 만료 전 같은 명령을 다시 실행하면 CA는 그대로 두고 서버 인증서만 갱신)
                   휴대폰: http://192.168.35.92:5050/install → '인증서 받기'로 lan-ca.crt 설치·신뢰(최초 1회)
                           → https://192.168.35.92:5443/install 에서 앱 설치
                   코드 반영 시 두 서비스 모두 재시작: launchctl kickstart -k gui/$(id -u)/kr.aiv2g.dev-https
                   두 포트가 로그인을 함께 쓰려면 .env의 SESSION_SECRET이 고정돼 있어야 한다(현재 설정됨).
  * 앱 객체는 src.api:app 이다(예전 문서의 src.api.main:app 은 존재하지 않는다).
  * [주의] 서버 PC의 다른 서비스 포트는 쓰지 않는다: 80→3000(Node 앱), 5000(macOS AirPlay), 8000·8443(Proposal AI Studio),
    8080(Docker), 8090(정적 파일). 6000번은 브라우저가 막는 포트라 쓰지 않는다. 다른 서비스의 폴더·프로세스는 건드리지 않는다.
  * 내부망 전용이다. 5050·5443 포트를 공유기 포트포워딩·터널로 외부에 열지 않는다. 서비스가 안정되면 다른 서버로 이관한다.
  * macOS에는 LightGBM이 쓰는 libomp가 없어 run_dev_lan.sh가 scikit-learn에 포함된 libomp를 잡아 준다(Homebrew 불필요).

[4단계] 브라우저 접속 (내 PC면 127.0.0.1, 사내망이면 192.168.35.92)

  ① 실적 계측(추론): 차량·일 피크(17~21시) 방전 kWh·과잉발전 흡수 kWh·요금 절감액.

  [1건 정의] 유효 이벤트 1회(차량 운행·차량 충전·거점 충전) × [① 차량·충전기 결합 블록 + ② AI 학습 블록(같은 1시간 외부환경)].
        src/pipeline/dataset.py build_dataset/summarize, GET /kpi/dataset(?sample=). 연차별 성과 건수(summarize_kpi)는 grid_df가 있으면
        결합 레코드 기준(① 필수 충족 ∧ ② 결합 성공)으로 센다. 서포터즈 충전이 연계 충전기에서 일어나면 그 세션을 A형 충전에 결합(±1시간).
  [산식] N = {30대 × (충전 주 3.0회 + 운행 주 d회) × 13주 × (1 − 16%) + 거점 주 250세션 × 13주} × 결합 성공률 r
        → d=0(보수적) 4,233건, 목표 4,000건 조건 r ≥ 94.5%. 입력값은 config/data_plan.json plan_inputs(kpi.build_data_plan).
        주간 점검: 운행이 계획에 없으면(d=0) OBD 계획 대비율은 충전 건만 비교하고 운행 건은 obd_drive로 따로 표시.
        본 수집 기간: data_plan.json collection.start/end(마일스톤 확정 후 입력, null이면 최근 13주).
  [AI 학습] build_city_hourly(..., charger_df=)가 거점 세션(서포터즈 제외)을 시간 단위 kW로 배분(site_charging_demand_kw)해
        학습 라벨 ev_charging_demand_kw = 서포터즈 OBD 충전 + 거점 충전. 대시보드·모델 평가·예측 서비스·재학습·Closed-loop 모두 같은 구성
        (합성은 src/datagen/scenario.py). 합성 거점 세션 시작 시각은 시간대 분포(START_HOUR_WEIGHTS, 가정값)를 따른다.
  [충전 인증 태그] 서포터즈 충전카드·RFID(OCPP idTag) ↔ 차량: src/registry/charge_tags.py(태그 원문 미보관, HMAC 가명 PT-…),
        POST/GET/DELETE /cpo/charge-tags. CPO 수신(POST /cpo/ingest/{cpo_id})은 이제 curated.db charger_sessions에 저장하고
        id_tag로 ev_id를 채운다(id_tag는 저장하지 않음).
  [B형 차량 블록] 충전기 세션 선택 항목 soc_start_pct·soc_end_pct·vehicle_model(스키마·CPO 수신·어댑터) — CPO 데이터 제공 범위 요청.
  [예측 대상] 주 = 시간대별 EV 충전수요(kW), 보조 = EV 가용 배터리 자원(kWh). 전력수요는 입력 변수(forecast_service.ALLOWED_TARGETS에서 제외).
        '4종'은 V2G BM 레퍼런스(수익 산정·모의 정산·VoC·벤치마크)에만 쓴다.
  [참고] 합성 기본 시나리오 충전수요 예측 정확도: 거점 세션 포함 전 69.6% → 포함 후 65.8%(R² 0.92→0.79) — 거점 세션의 무작위성 때문.
        실측 데이터로 다시 평가 필요.
