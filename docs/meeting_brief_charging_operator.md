# AI-V2G 기능명세 및 서비스 영역 실증 검증 요약 — 충전사업자(CPO) 미팅용

기준일 2026-10-23. 코드·테스트(전체 597건 통과)와 데모 서버 산출값에서 추출했다.
**수치는 모두 합성 데이터·가정값 기반 모의 결과(`is_real_data=false`, `verified=false`)이며 실증 성과가 아니다.** 미팅에서 이 구분을 먼저 밝힌다.

## 1. 한 장 요약

AI-V2G는 차량(OBD)·충전기·전력 신호를 모아 **충전 시간을 싼 시간대로 옮기고, 방전이 이득일 때만 방전**하도록 계획한다.
차주에게는 모바일웹으로 안내하고, 충전사업자에게는 OCPP로 스케줄 명령을 전달하는 구조다.
이동권(출발 시 필요 잔량)과 배터리 안전이 항상 경제성보다 우선이며, 방전 참여는 **기본 꺼짐(옵트인)·언제든 철회**다.

## 2. 기능명세 (구현 상태별)

| 영역 | 기능 | 상태 | 근거 |
|---|---|---|---|

| 데이터 수집 | 충전기 세션 연동(CPO 어댑터·동기화) | 구현(어댑터 틀) | `src/cpo/` — 사업자별 API 명세 필요 |
| 예측 | 충전 수요·V2G 가용량(일/주/월 전망), 차량별 입출차 패턴 | 구현 | `/forecast/*`, 모델 레지스트리·재학습 판단 |
| 최적화 | 군집 충·방전 최적화(MILP), 차량별 SoC 플래너, 열화비·손익분기 반영 | 구현 | `src/optimizer/` |
| 최적화 | 일반충전 대비 피크·비용 비교, 이익 배분 시뮬레이터 | 구현(모의) | `/optimize/poc-compare`, `profit_sharing` |
| 충전기 제어 | CEMS 스케줄을 CSMS 경유 OCPP 명령으로 전달, 가상 충전기 에뮬레이터 | 구현(에뮬레이터 기준) | `/ocpp/*` — 실제 충전기 접속은 미검증 |
| 전력망 | DR 이벤트 등록·에뮬레이션, DR 실적, KPX SMP 연동 | 구현(DR은 에뮬, SMP는 키 필요) | `/grid/*` |
| 재생에너지 | 태양광 연계 충전소 모의(즉시충전 vs 태양광 우선), 나주 지역 모델 | 구현(가정값) | `/solar/*` |
| 안전 | 최적화와 별개 코드의 독립 검증(출발 잔량·예비 20%·용량·방전 35~80%·동시 금지·참여), 실패 시 방전 없는 계획으로 복귀 | 구현 | `src/advisory/safety_guard.py` |

| 실험·인센티브 | 실험군/대조군 배정, 동의 차량 인센티브 정산 미리보기 | 구현(미리보기) | `/experiment/*` |

## 3. 서비스 영역 실증 검증 (데모 데이터, 30대·150기·21주)

| 검증 항목 | 결과 | 해석 |
|---|---|---|
| 규모 구성 | EV 30대, 충전기 150기, 사업자 2개, 차종 5종 | 계획서 목표(30대·150기·2개사·2종) 충족 구성 |
| 내부 데이터 건수 | 6,063건 (목표 5,500) — 충전세션 1,653 + 차량-일 4,410 + 방전 0 | 방전 이벤트 100건 목표는 **0건** — 실제 방전 차량·충전기 확보가 관건 |
| 외부 연계 데이터 | 0건 (목표 14,000, 실데이터만 인정) | 한전·공공데이터 키 발급 후 집계 |
| 데이터 품질 | ev_telemetry 105,840행·charger_sessions 4,369행·grid_signal 3,528행 모두 통과 | 합성 데이터 기준 |
| 비용 절감(모의) | 일반 6,667,027원 → AI 5,422,109원, 절감 1,244,917원(18.7%) | 가정 요금표·방전 보상 기준. 열화비 단가 46.7원/kWh, 효율 92% |
| 이익 배분(모의) | 차주 50% / 사업자 30% / 플랫폼 20% | 실제 정산 아님 — 배분 비율은 협의 대상 |
| 수요 예측 | 충전 수요 MAE 5.36 kW(검증 구간), 홀드아웃 6.30 | 합성 데이터 적합도. 실데이터 재검증 필요 |
| 재학습 판단 | 신규 주 드리프트 2.8% < 임계 20% → 재학습 불필요 | 폐루프 자동 판단 동작 확인 |
| V2G 가능 차량 | 시뮬 30대 중 17대가 가능으로 설정 | **실증에 쓸 수 있는 실제 방전 가능 차량은 확인되지 않음** |
| 충전기 이용률 | 평균 4.3%, 피크 18.8% | 합성 부하 기준 |
| 안전 검증 | 6개 항목 단위·통합 테스트 통과, 방전 참여 기본 꺼짐 | 최적화 결과를 독립 재검증 |

주의: 비용 절감은 합성 부하에서 요금 차이로 만든 값이다. 일일 피크(kW)는 일부 날짜에 오히려 올라가므로(최적화가 저가 시간으로 몰기 때문)
"피크 감축"을 주장하려면 피크 제약을 둔 시나리오로 따로 검증해야 한다. 미팅에서 확정 성과처럼 말하지 않는다.

## 4. 충전사업자에게 확인·요청할 사항

1. **OCPP 버전·기능**: 1.6J / 2.0.1, `SetChargingProfile` 지원 여부, 시험용 충전기 또는 CSMS 샌드박스 제공 가능 여부.
2. **충전 세션·계측 데이터**: 세션 로그, 충전기 계측 kWh(차량 OBD 대비 손실률 검증용), 제공 주기와 형식, 개인정보 가명처리 방식.
3. **양방향(V2G) 충전기 보유**: 방전 가능 충전기 대수·모델. 없으면 방전 이벤트 100건 목표는 시뮬레이션으로만 가능.
4. **요금·보상 체계**: 시간대별 충전 단가, 방전 보상 단가(손익분기 예: 충전 295원이면 약 399원/kWh 이상이어야 이득), 사업자 몫 30% 가정에 대한 의견.
5. **운영 정책**: 스케줄 명령을 받을 수 있는 시간대·상한 kW, 피크 요금·DR 참여 여부, 이용자 충전 우선 정책.
6. **보안·책임**: 명령 채널 인증(TLS·인증서), 장애 시 즉시 해제 절차(`clear-ai-schedule`), 개인정보 처리 위탁 범위.
7. **일정**: 사업자 2개사 이상 참여, 데이터 제공 시점, 현장 시험 가능 기간.

## 5. 한계 (정직하게 말할 것)

- 모든 경제성·예측 수치는 합성 데이터와 가정값이다. 요금표·방전 보상 제도가 확정되지 않았다.
- 실제 충전기와의 OCPP 연동은 에뮬레이터에서만 확인했다.
- 방전 이벤트 실측 0건, 외부 연계 실데이터 0건.
- 모바일 알림과 일부 화면(가입·마이페이지·PC 승인)은 서버 기능만 있고 화면은 예정이다.
- ISO/IEC 42001은 인증 취득이 아니라 "체계 정합성 확보" 수준으로 표현한다.
