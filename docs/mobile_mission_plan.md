# 모바일 미션·포인트 기획안 (로드맵 5단계 M)

상태: **기획 초안** — 구현 전. 이 문서의 수치·규칙은 제안이며, 지자체·사업 담당 협의와 이용자 검증으로 확정한다.
근거: `docs/owner_web_roadmap.md`(5단계 M, 결정 사항), 사업수행계획서의 인센티브 문구("포인트·할인·배분 인센티브 모델(안) — **실금 정산 아님**"),
기존 구현(`src/experiment/incentive.py`·`config/incentive_policy.json`, 동의 목적 `incentive`·`v2g_discharge`).

## 1. 목적과 원칙

목적: 이용자가 **안전한 범위에서** 충전 시간 이동·방전 참여·앱 활용을 꾸준히 하도록 돕고, 실증 데이터(참여율·수용률)를 쌓는다.

| 원칙 | 의미 |
|---|---|
| 이동권·배터리 안전 우선 | 미션이 과충전·무리한 방전·출발 잔량 미달을 유도하지 않는다. 안전 검증(`safety_guard`)을 통과한 추천만 미션 대상이다 |
| 옵트인·철회 | 방전 관련 미션은 방전 참여를 켠 이용자에게만 보인다. 포인트는 `incentive` 동의가 있을 때만 적립한다. 철회하면 적립을 멈춘다 |
| 실금 정산 아님 | 포인트는 **모의(시범) 보상**이다. 계획서의 "실금 정산 아님"과 충돌하지 않게 화면·문구에 "시범 포인트"로 표기한다 |
| 최소 수집 | 미션 판정은 이미 있는 데이터(추천 이력, 방전 이벤트, 알림 응답)로 한다. 새 개인정보를 받지 않는다 |
| 과장 금지 | 금액·효과는 가정값 기반 모의임을 항상 표시한다 |

## 2. 미션 유형 (제안)

| 유형 | 예시 | 판정 데이터 | 비고 |
|---|---|---|---|
| 시작하기 | 알림 수신 켜기, 충전 시간 안내 처음 확인, 방전 참여 설정 보기 | 동의·화면 호출 기록 | 1회성, 낮은 포인트 |
| 추천 따르기 | 추천 충전 시간대에 충전 시작, 이번 주 추천 3회 수용 | 추천 이력(`advisories`)의 수용·응답 | 수용률 KPI와 연결 |
| 피크 피하기 | 수요 높은 시간대(18~21시) 충전 피하기 | 충전 세션 시각 | 안전·이동권 영향 없는 범위 |
| 방전 참여 | 방전 허용 구간에서 방전 이벤트 달성 | 방전 이벤트(`discharge_events`), 참여 동의 | 방전 가능 차종·참여 ON만, 월 한도 |
| 안전 지킴이 | 출발 시 목표 잔량 달성, 예비 잔량 유지 | 안전 검증 로그 | 방전 미션과 함께 "안전 우선" 강화 |

**하지 않는 것**: 순위 경쟁(과도한 방전 유도), 연속 일수 압박(streak 소멸 불안), 잔량을 낮추도록 하는 미션.

## 3. 포인트 규칙 (제안, 가정값)

- 기본 단가·피크 가산·월 상한은 기존 `config/incentive_policy.json`(방전 1kWh당 100점, 18~21시 1.5배, 월 50,000점, 1점=1원, `verified=false`)을 재사용한다.
- 미션 보상은 별도 표로 관리한다(예: 시작하기 50점, 추천 수용 20점/회, 주간 달성 100점). **수치는 협의 전 예시이며 `config/missions.json`(신규)에 `verified=false`로 둔다.**
- 이중 적립 방지: 같은 방전 이벤트는 정산 포인트와 미션 포인트 중 **한 번만** 인정한다.
- 월 상한: 차량당 합계 상한 적용. 상한 도달 시 안내 문구 표시.
- 포인트 유효기간·소멸 정책은 지자체 협의 후 결정(미정).

## 4. 교환(시범)

로드맵 결정 사항 유지: **문화상품권 시범** — 이용자가 교환 신청 → PC 관리자가 상품권 코드를 입력(암호화 저장) → 모바일 쿠폰함으로 전달. 자동 발급 API 연동 없음.

선행 확인(코드로 해결 불가): 상품권은 실제 금전적 보상이라 **"실금 정산 아님" 문구와 충돌**한다. 지자체·사업 담당과 협의해 계획서 문구를 맞추고,
5만 원 초과 경품 세금(원천징수) 처리를 확인한다. 협의 전에는 **교환 기능을 비활성(화면 숨김 또는 "준비 중")** 으로 둔다.

## 5. 데이터 모델·API 초안

| 항목 | 내용 |
|---|---|
| `missions`(설정) | 미션 ID, 유형, 조건, 보상 점수, 대상(방전 가능·참여 ON 여부), 기간 |
| `mission_progress` | 차량(ev_id)·미션·진행값·달성 시각 — 달성 판정은 서버가 기존 로그에서 계산 |
| `point_ledger` | 적립·사용 내역(이력 삭제 없이 누적), 사유·출처 이벤트 ID, 정책 버전 |
| 이용자 API | `GET /owner/missions`(목록·진행), `GET /owner/points`(잔액·내역), `POST /owner/points/redeem`(시범 교환 신청) |
| 관리자 API | `GET/POST /rewards/redemptions`(신청 목록·코드 입력), 미션 설정 조회 |
| 알림 | 미션 달성 시 알림함에 생성(알림 수신 동의 시, 시범 포인트 표기) |
| 감사 | 적립·교환·코드 입력은 해시체인 감사로그에 기록(번호판 등 식별정보 제외) |

서버가 판정하며, 클라이언트가 달성 사실을 보내는 방식은 쓰지 않는다(조작 방지).

## 6. 화면 (모바일 · PC)

모바일(기존 탭에 **"미션"** 탭 추가, 알림·충전 시간·예측 옆):
1. 미션 목록 — 진행 막대, 남은 기간, 안전 문구("잔량을 낮추는 미션은 없어요")
2. 포인트 — 잔액, 적립 내역, "시범 포인트·실제 정산 아님" 고지
3. 쿠폰함 — 교환 신청·전달 상태(협의 전 비활성)

PC 대시보드: "리워드" 화면 — 교환 신청 목록, 상품권 코드 입력, 적립 현황 요약, 월 상한 도달 차량.

## 7. 부정 사용·개인정보

- 판정은 서버 로그 기준이라 클라이언트 조작이 불가능하다. 동일 이벤트 중복 적립은 이벤트 ID로 차단한다.
- 포인트 이력은 회원 탈퇴 시 삭제 대상에 포함한다(보유기간은 `config/retention.json`에 항목 추가).
- 개인정보 처리방침·동의 문구에 포인트 적립·교환 항목을 추가해야 한다(법무 검토 필요).

| M1 | 서버: 미션 설정·진행 판정·포인트 원장·이용자 API·테스트 | 교환 제외 |

## 9. 확정이 필요한 결정

1. 상품권 교환을 시범에 포함할지, 포인트 적립까지만 할지(문구 충돌 해소 방향).
2. 미션·보상 수치와 월 상한, 포인트 유효기간.
3. 방전 미션의 월 이벤트 한도(배터리 열화 고려, 현재 최적화는 하루 방전 2회 한도 가정).
4. 미션 대상: 전체 이용자인지, 방전 가능·참여 ON 이용자만인지.
5. 포인트 처리 위탁·보유기간 등 개인정보 처리방침 반영 범위.

## 10. 미션 확인 방법 — "안내대로 했는지" (구현됨, 2026-10-23)

| 구분 | 확인 방식 | 신뢰도 |
|---|---|---|
| 안내 확인형(시작하기·주간 확인·안전 통과 안내) | 서버가 감사로그에서 계산 | 낮음 → 포인트 낮게 |
| **추천 충전형**(`follow_charge_weekly`) | 안내 발급 때 저장한 추천 시간대(`guide_plans`)를 실제 충전 기록(OBD 시간별 충전 kW)과 대조 | 높음 → 포인트 높게(200점) |

- 달성 기준(`config/missions.json`의 `verification`, 협의 전 예시값): 추천 시간대 ±1시간 안에 실제 충전량의 **70% 이상**, 실제 충전량이 추천량의 **50% 이상**.
  같은 날 안내를 여러 번 받아도 하루 한 번만 센다. 일정 때문에 못 맞춘 경우 감점하지 않고, 달성하면 가산만 한다.
- 상태: `ok`(확인됨) / `pending`(충전 기록이 출발 시각까지 아직 없음) / `unavailable`(충전 기록이 없는 차량 — 모바일 가입 직후 OBD 미설치) / `tracking`.
  OBD가 없는 차량은 이 미션을 달성할 수 없고, 화면에 "충전 기록(OBD)이 연결된 차량에서 확인돼요"로 안내한다.
- 한계: 현재 충전 기록은 합성 데이터라 시연에서 실제 값이 나오려면 기록이 안내 시각 이후까지 있어야 한다. 방전 미션은 방전 이벤트 기록이 생기면 같은 방식으로 추가한다.
